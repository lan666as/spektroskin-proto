## 5. Virtual optical module (backend/simulator)

Generate phantom frame sets with KNOWN ground truth. Simplified, illustrative model
(label it as such; real skin involves scattering this ignores):

- Ground-truth maps per phantom: melanin `m(x,y)` and hemoglobin `h(x,y)`, on a skin
  baseline with adjustable background melanin (3 skin-tone levels, light/medium/dark).
- Phantom types: pigmented lesion, vascular lesion, mixed lesion. 3 types × 3 tones = 9.
- Bands: blue (~470 nm), green (~550 nm), red (~660 nm), NIR (~850 nm), plus a dark frame.
- Reflectance per band: `R_b = R0_b * exp(-(k_mel_b * m + k_hb_b * h))`.
  Illustrative coefficients: k_mel decreases blue→NIR (1.0, 0.7, 0.4, 0.2);
  k_hb high in green, moderate blue, low red/NIR (0.6, 1.0, 0.1, 0.05).
- Raw frame: `I_b = gain_b * illum_b(x,y) * R_b + ambient + noise`, with vignetting
  in `illum_b`, small random x/y shift per band (hand motion), and gray reference
  patches of known reflectance (e.g. 0.18 and 0.50) in a ring at the frame edge.
- Device profile (one-time "factory calibration"): per-band flat-field frames and
  dark frame, saved alongside.
- Output: PNG frames (16-bit if practical) + `meta.json` + `ground_truth.npz`.
  Write a copy of the frame sets (not ground truth) to `mobile/assets/phantoms/`.
- Optional "bad capture" variants (blurred, glare) to demo the QC gate.

## 6. Processing pipeline (backend/app/processing)

Order: QC → registration → calibration → spectral maps → segmentation.

1. QC (real, classical): sharpness via Laplacian variance, glare = % saturated pixels,
   reference patches detected. Return pass/fail + human-readable retake guidance.
2. Registration: align each band to the green band (phase correlation).
3. Calibration: dark subtraction, flat-field correction, gain-drift correction using
   reference patches → reflectance per band.
4. Spectral maps: per-pixel linear unmixing of `-ln(R_b / R0_b)` across 4 bands
   (least squares) → estimated melanin map ("pigment view") and hemoglobin map
   ("vascular view"). Also a pseudo-RGB "standard view" from blue/green/red.
5. Segmentation: threshold (e.g. Otsu) on the pigment or combined map → lesion mask,
   area in mm² (assume a fixed px→mm scale from the spacer), outline overlay.

Outputs saved as PNG overlays plus a JSON result.
Stretch — validation: compare recovered maps with ground truth (correlation, RMSE,
mask Dice) and expose `GET /validation/{capture_id}`.
Tests: pytest that the pipeline recovers ground truth within tolerance on clean
phantoms, and that QC rejects the blurred/glare variants.

## 7. Data model (SQLAlchemy ORM on Postgres)

Conventions: UUID primary keys, `timestamptz` timestamps (UTC), JSONB for
structured results, status/enum fields as text with CHECK constraints, foreign keys
with indexes, an index on `cases.status`.

- Patient: id, code (pseudonymous, unique, e.g. "PT-0007"), age, sex, fitzpatrick (I–VI), created_at
- Lesion: id, patient_id, body_site (incl. acral sites: palm, sole, nail), created_at
- Capture: id (client-generated UUID, makes upload idempotent), lesion_id, captured_at,
  device_type ("virtual"), phantom_id, qc (JSONB), result (JSONB), status
- Case: id, lesion_id, question, status (submitted | in_review | answered), timestamps
- CaseCapture: case_id, capture_id (join table)
- Review: id, case_id, reviewer, impression, action (observe | biopsy | refer),
  follow_up_days, notes, created_at
- AuditEvent: id, actor, action, entity_type, entity_id, at — written on every read/write of patient data
